What it names

Before it breaks, and as it breaks.

Every result says whether the failure is predicted or already happening, the measurement behind it and what to do. It also lists the pods closest to their limit, so a quiet cluster still shows what is watched.

Predicted

With a time and a window, from trends and from history.

  • Memory or disk heading to its limitTheil-Sen trend
  • Failure that returns on a rhythmfailure memory
  • One replica leaking, its siblings flatreplica divergence
  • New release growing faster than the lastfirst 2 h after rollout

Detected

As Kubernetes reports them, explained, often minutes before a default rule fires.

  • Crash loop, OOM killwith its cause
  • Image pull, missing mount, unschedulablestartup stuck
  • Stuck rollout, missing replicasworkload state
  • CPU throttled most of the timecgroup periods

How it fits

Nothing new to run on your workloads.

  • Reads what you haveThe cluster's Prometheus or Thanos and the Kubernetes API. No sidecar, no agent, no code change.
  • Speaks where you lookNative alerts in Alertmanager and the OpenShift console, its own console, and a REST API.
  • Knows who calls whomBuilds the call graph from Services, Routes and env, and names the callers a failure can take down.

Measured, losses included

Against the rules teams write today.

Six hours on our OpenShift lab on 9 November, pre-registered before any data. The opponent is predict_linear over 30 minutes on the same metrics.

Helm, engine only

helm install ruptura \
  oci://ghcr.io/benfradjselim/charts/ruptura \
  -n ruptura-system --create-namespace \
  --set thanos.url=<your-prometheus>

On your laptop

git clone https://github.com/benfradjselim/ruptura
cd ruptura && docker compose up --build

Then open localhost:8081 to try it on demo workloads.

# the operator
oc apply -f https://raw.githubusercontent.com/benfradjselim/\
  ruptura/main/install/operator.yaml

# one instance
apiVersion: ruptura.io/v1alpha1
kind: RupturaInstance
metadata: {name: ruptura, namespace: ruptura-system}
spec:
  level: {scope: workload}
  output: {ui: {enabled: true}}
